# AI 费曼学习法

## 这个 skill 在干什么

费曼学习法大家都知道，但大多数人只做了前半段：讲一遍，感觉懂了，结束。真正管用的部分在后面——合上材料自己讲，然后被人戳穿哪里其实没懂。

这个 skill 就是把后半段补上。讲完不算完，得让用户闭卷复述，用一组探针找出他自以为懂、其实没懂的地方，回源补上，反复到每个概念都过得了四道门，才允许写笔记。

## 五条铁律

1. **教练阶段不给答案。** Phase 3–5 期间，正确答案一个字都不能漏——包括拆成「提示」分几次喂、用反问暗示。你一说答案，学习就结束了，而用户还以为自己懂了。卡死了怎么办？用**窄带重讲**，不是给答案。细则见 `references/probing.md`。
2. **不凭记忆讲解。** 数字、默认值、名称、顺序、API 签名、版本行为、因果关系，都得这一轮实际读到过。记忆和抓取结果打架，听抓取的。查不到就写 `未知`。细则见 `references/sources.md`。
3. **致命 gap 没闭合，别进 Phase 6。** 机制链还断着就写笔记，等于把错误理解钉进文档。脚本在 mastery 上封顶 0.4 兜底，触发条件靠两道校验：severity 必须跟 score 绑定（`score 0` 不能标成「细节」绕过去），`resolves` 里的 gap 必须属于本轮真考过的概念。不过内容判得准不准，还是你的事——脚本只管结构自洽。
4. **判分不放水。** `score 2` 就是四道门全过，没有「鼓励一下」的余地。放一次水，mastery 和 SM-2 排期全歪，而且退不回来。
5. **一次问一个。** 一口气抛五个问题，用户只会挑最容易的答，剩下的 gap 全被盖住。

## 入口判断

先看这是新主题还是续学：

```bash
node <skill-dir>/scripts/feynman.mjs status <slug>
```

- 报「主题不存在」→ 新主题，从 Phase 0 开始。
- 有状态 → 看 `status` 最后那行 `NEXT:`，接着做就行，别从头重讲。已经达标又到复习期的概念，走 `test --due-only`。

工作区默认落在 `<项目根>/feynman/<slug>/`（脚本从 cwd 解析 `--dir`，默认 `feynman`）。

下面命令里的 `<skill-dir>` 指本 skill 的安装目录：

- Codex 用户级安装 → `~/.codex/skills/ai-feynman`（Windows：`C:\Users\<你>\.codex\skills\ai-feynman`）
- 在仓库里开发 → `skills/ai-feynman`

**cwd 必须留在项目根**，工作区才会落在项目里；脚本会检查 cwd 有没有 `.git` / `.codex` / `.qoder` / `.agents` 标记，缺了直接报错，避免在子目录里静默分裂出第二份工作区。脚本每次输出的 `NEXT:` 行里带的是可直接复制的完整命令，优先照它执行。

**规模自适应**——小题别上全套流程：

| 规模 | 概念数 | 做法 |
|---|---|---|
| 微 | 1–2 | 一次会话跑完 Phase 0–4；笔记和可视化看需要，能跳 |
| 标准 | 3–9 | 完整闭环，一般要跨几次会话，靠 `status` 续接 |
| 大 | >9 | 拆成几个主题分别 `init`，别硬塞进一个 slug |

## 七阶段状态机

### Phase 0 定标

把模糊的主题拆成**可证伪**的概念清单。

1. **先判起点**：外行 / 有基础 / 熟手。看他怎么描述需求、用了哪些词、以及「你现在是怎么做这件事的」怎么答。这一步定下来，后面所有问题的问法都跟着变。
2. 问清学习目标（调试 / 面试 / 设计决策 / 教学 / 纯兴趣）——它决定讲多深、题往哪偏。
3. 确认材料从哪来：用户给的路径、URL、主题名，还是什么都没有（那就走网络检索）。
4. 拆概念。每个概念配 `pass_criteria`，而且得能被一个具体问题判出通过与否。「理解 X」不行，「能说出 X 失效的两种输入」行。
5. 落盘：

```bash
node <skill-dir>/scripts/feynman.mjs init <slug> --title "<标题>" --target "<为什么学>"
node <skill-dir>/scripts/feynman.mjs concepts <slug> --file concepts.json
```

**只问用户答得上来的问题。** 学科内部的事是你的活，不是他的。

- 可以问：他的目标、他现在的做法、他卡在哪、手上有哪些材料或具体案例
- 别问：让他审阅或增删你拆的概念清单、让他在信源分级里取舍、让他在两条技术路线里挑一条、让他指定练习样本的专业参数

**起点是外行时**：范围和信源你全权决定，告知就行，不用征求意见；首轮概念 ≤3 个，而且必须从前置概念起步——连「这份材料是什么、谁写的、能不能信」都还没建立就开讲细分主题，前几轮基本空转。需要样本（公司、代码库、案例）你自己挑，顺便说明为什么挑它；概念清单分轮增量注册（`concepts` 会保留已有 mastery），别一次塞满。

判断错起点比拆错范围更贵：范围错了能重拆，起点错了整轮学习都白费。

**出口**：概念注册好了，每个都有非空 `pass_criteria`。

### Phase 1 取证

按输入类型走 `references/sources.md` 里对应的流程（代码库 / 论文规范 / 课程考点 / 链接碎片 / 网络检索）。

要点：信源分 T1–T4；具体断言必须有 T1；每条 claim 记进 `sources.md`，带上抓取日期和 `已验证 / 推断 / 未知`。用户只给主题的时候，先把分级信源候选列出来让他确认，再往下抓——别闷头读完一堆低质内容就开讲。

**出口**：每个概念至少 1 个 T1 信源。拿不到的标 `信源不足`，这个概念不出 `score 0` 的判定题，并且明确告诉用户。

### Phase 2 深讲

分层讲，从粗到细。用户在哪一层喊停都行：

1. **一句话本质** — 不许用领域术语
2. **类比** — 必须同时说清它在哪儿失效：「这个类比在 X 处不成立」
3. **机制链** — A →(主语+动作)→ B →(主语+动作)→ C，不许出现「然后就…」「自然就…」
4. **边界与代价** — 什么时候失效、牺牲了什么、什么情况下不该选它
5. **常见误解** — 包括 `sources.md` 里登记的信源冲突，和 T4 上流传的错误说法

机制类主题在这里出可视化图（规格见 `references/artifacts.md`），图里必须画出失效路径，不能只有 happy path。

同时写 `bank.json` 并校验：

```bash
node <skill-dir>/scripts/feynman.mjs bank <slug> --check
```

**讲之前先自检**（`references/probing.md` 末节）：拿同一套九检测器审自己的讲解。自检不过就先改讲解——你讲解里每个 gap，用户都会原样继承，而且因为是你说的，他不会怀疑。

**出口**：`bank --check` 过了，自检也过了。

### Phase 3 复述 ← 闭环从这里开始

换角色。让用户**闭卷**讲一遍：不看源材料、不看 `notes.md`、不看讲义。

- 开场只用 L0：「不看材料，把 X 讲一遍。」说完就安静，等他把话讲完。
- 最值钱的 gap 往往在复述的后半段冒出来，别中途打断。
- 不打断、不纠正、不补引导。
- 后面按 `references/probing.md` 的 L0→L5 阶梯逐级追问，一次升一级，一次问一个。
- 机制类主题可以在 **L2** 把可视化图拿出来，让用户指着图讲：他在哪个节点卡住、哪条边说不出触发条件，gap 就在那儿。L0 阶段别给图——图会替他把机制链讲完，诊断价值就没了。

### Phase 4 挑漏

对着四道门（G1 无术语复述 / G2 机制链 / G3 边界 / G4 反例存活）判分，用九检测器给每个 gap 归类。

判分和 gap 类型写进 `results/sN.json`（`test` 已经生成好模板）。**每道题都要填 `gates: {G1,G2,G3,G4}` 四个布尔值**——脚本会查它和 `score` 对不对得上：四门全 true 才能给 `score 2`，缺 G1/G2 才能给 `score 0`。逐门写下来，「通过」才经得起复核；不写，它就只是个印象分。`note` 里要摘用户原话：

```bash
node <skill-dir>/scripts/feynman.mjs record <slug> --results feynman/<slug>/results/sN.json
```

脚本会更新 mastery、SM-2 排期、往 `gaps.md` 追加记录，然后输出 `NEXT:` 行。按 `NEXT:` 走。

### Phase 5 回源

每个 gap 都给**精确**的回源坐标，不是「再去读一遍第三章」：

- 代码：`path/to/file.ts:1180`，说清看哪个分支
- 论文/规范：`§3.2` / `RFC 9110 §8.3` / 具体页
- 网页：`URL#anchor`

用户只读这些。读完回 Phase 3，**只对没过的那几个概念**重新出卷：

```bash
node <skill-dir>/scripts/feynman.mjs test <slug> --concepts <弱项id列表> --n 4
```

**循环上限**：同一个概念连着 3 轮不过 → 停下来，改用窄带重讲（只重讲卡住的那一个子步骤）；再不过说明前置概念缺了 → 回 Phase 0 补一个前置概念，别硬推。

闭合的 gap 一定要在 `results` 的 `resolves` 里填上 `gid`，不然致命 gap 永远不解除，mastery 就一直被封在 0.4。

**出口**：没有未闭合的致命 gap，各概念 mastery ≥ 0.8（看 `status`）。

### Phase 6 固化

照 `references/artifacts.md` 的模板写 `notes.md`。

第 4 节「我曾以为」是整份笔记最值钱的地方，必须拿 `gaps.md` 里用户的原话整理，别美化成中性描述。「我原以为 render 阶段 setState 没问题」是能复现的心智模型诊断；「对 render 阶段纯度要求理解不足」听着没错，但没有任何诊断价值。

最后跑一下 `status`，把下次复习时间告诉用户。

## 脚本命令速查

```
init      <slug> --title "标题" [--target "..."] [--dir feynman]   创建工作区
concepts  <slug> --file concepts.json                              注册概念（保留已有 mastery）
bank      <slug> --check                                           校验题库
test      <slug> [--n 8] [--concepts a,b] [--due-only] [--seed S]  加权抽样出卷
record    <slug> --results results/sN.json [--session sN]          判分落账
status    <slug>                                                   进度看板 + NEXT 建议
```

脚本干的都是确定性簿记（抽样、SM-2、mastery、gap log），判分永远是模型的事。脚本查的是**结构自洽**——四道门和 score 有没有打架、severity 跟 score 配不配、闭合的 gap 是不是本轮考过的，内容对不对它不管。抽题按 `(1-mastery)^1.5 × (1+0.2×lapses) × 难度系数` 加权，`apply` 题还要求该概念 mastery ≥ 0.8 且没有未闭合致命 gap 才进候选池，同时分层保证概念覆盖广度。

参考答案和 `source_ref` 只留在 `bank.json`，别粘进试卷或对话——闭卷才有诊断价值。

## 常见的几种走偏

- **变成讲解器**：讲完就收工，Phase 3 跳了。没有复述就没有诊断，用户带走的是「听懂了」的错觉。
- **让外行做专家决策**：把概念清单、信源分级、技术路线摆到初学者面前让他挑。他对这些取舍没有判断依据，问了只会卡住或者随手点一个。范围和取舍是你的责任，你只需要问他的目标、现状和困惑。
- **提前给答案**：用户卡两次就心软。参见铁律 1。
- **凭记忆开讲**：跳过 Phase 1，把训练数据里过时或错误的内容当事实教出去。参见铁律 2。
- **一次抛多问**：用户挑最容易的答，gap 被盖住。
- **放水判分**：为了气氛给 `score 2`，mastery 和排期全被污染，而且退不回来。
- **泛泛回源**：「再去看看文档」。得给到行号/章节/锚点。
- **省略边界题**：只出 `explain` 和 `mechanism`，用户永远过不了 G3，脚本会告警。
- **笔记第 4 节被压缩**：Gap 复盘写成一行总结，笔记就失去了唯一不可替代的部分。
