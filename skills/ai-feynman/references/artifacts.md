# 交付物规范

下面三个 JSON schema、费曼笔记的写法、可视化图的规格。schema 跟 `scripts/feynman.mjs` 的校验规则**一一对应**，字段缺了脚本会直接拒绝。

## concepts.json（Phase 0 产出）

```json
[
  {
    "id": "lane-prio",
    "title": "Lane 优先级模型",
    "pass_criteria": [
      "能解释 lane 为什么用位运算而不是优先级数字",
      "能给出一个低优先级更新被饿死的场景及兜底机制"
    ],
    "weight": 2
  }
]
```

- `id` — 小写字母开头，仅 `a-z 0-9 . _ -`。脚本用它做索引，改名会丢失 mastery 历史。
- `pass_criteria` — **必填且非空**。必须可证伪（能被一个具体问题判定通过/不通过）。「理解 X」不合格；「能说出 X 失效的两种输入」合格。
- `weight` — 默认 1。影响总 mastery 加权。核心概念给 2–3，边角给 1。
- 粒度：一个概念对应 15–40 分钟的一次复述。太粗（「React 调度」）无法定位 gap，太细（「某个变量名」）浪费轮次。一般 3–9 个概念。

## bank.json（Phase 2 产出，`bank --check` 校验）

```json
{
  "questions": [
    {
      "id": "q3",
      "concept": "lane-prio",
      "type": "mechanism",
      "difficulty": 2,
      "prompt": "为什么 lane 用 31 位 bitmask 而不是优先级数字？换成数字会遇到什么具体问题？",
      "reference_answer": "G2 判分要点：\n- lane 是 31 位 bitmask，每位代表一个优先级\n- 位运算可 O(1) 求交集/并集，一次表达并合并「一组」优先级\n- 用数字则每次只能比较单个优先级，批处理需遍历\nG3 加分：31 位受 JS 有符号位运算限制",
      "common_wrong": "只说「位运算更快」，没解释需要表达的是一组优先级的集合",
      "source_ref": "packages/react-reconciler/src/ReactFiberLane.ts:88"
    }
  ]
}
```

必填字段（缺一则脚本报错）：`id`（唯一）、`concept`（须已注册）、`prompt`（≥8 字符）、`reference_answer`（≥10 字符）、`source_ref`、`difficulty`（1/2/3）。

### type：每种题型对应一道门

| type | 考察 | 对应 |
|---|---|---|
| `explain` | 无术语说清是什么 | G1 |
| `mechanism` | 因果链，每步有主语和动作 | G2 |
| `boundary` | 失效场景与代价 | G3 |
| `counterexample` | 反例 / 替代设计对比 | G4 |
| `trace` | 给具体输入，逐步推中间状态 | G2 强化 |
| `compare` | 与另一方案权衡 | G3+G4 |
| `apply` | 迁移到未见过的新场景 | L5，仅达标后出 |

### difficulty 判据

- `1` — 单一概念复述，答案在源材料中直接可见
- `2` — 需串联两步以上或做机制推理
- `3` — 需边界判断、构造反例、跨概念迁移；**源材料中无现成答案**

### 出题规则

- 每概念 ≥ 3 题，且**必须**至少各 1 题 `boundary` 或 `counterexample`（缺边界题最容易留下理解幻觉，脚本会告警）。
- 难度分布约 `1:2:2`。总数 ≈ 概念数 × 3–5。
- `reference_answer` 不是标准答案全文，而是**判分要点**：逐门列出「必须出现的要素」。这让判分可复现，避免每次判分标准漂移。
- `common_wrong` 建议填：写出最可能出现的错误答案。判分时命中它 → 直接定位 gap 类型。
- `prompt` 里禁止出现答案线索或术语提示（「用位运算解释 lane」就泄题了）。
- `source_ref` 必须是**实际读过**的位置。回源全靠它，猜的行号会让 Phase 5 失效。

## results/sN.json（Phase 4 产出，`record` 消费）

`test` 子命令会自动生成模板。填完 `score` 后运行 `record`。

```json
{
  "session": "s2",
  "graded": [
    {
      "question_id": "q3",
      "score": 2,
      "gates": { "G1": true, "G2": true, "G3": true, "G4": true },
      "gap_type": null,
      "severity": null,
      "note": ""
    },
    {
      "question_id": "q2",
      "score": 0,
      "gates": { "G1": false, "G2": false, "G3": false, "G4": false },
      "gap_type": "边界失守",
      "severity": "致命",
      "note": "原话：「render 里 setState 应该没问题吧」——完全没意识到中断会导致重复执行"
    }
  ],
  "resolves": ["g1"]
}
```

- `session` — **活字段**。`record` 按它绑定 session（优先级：`--session` > 此字段 > 唯一待记录卷），写错会被拦下。
- `gates` — **每题必填**的四道门布尔证据。脚本校验它与 `score` 自洽：四门全 `true` 才能给 `2`，缺 G1/G2 才能给 `0`，缺字段直接报错。详见 `references/schema.md`。
- `score` — `2` 通过 / `1` 部分 / `0` 未通过。判据见 `probing.md` 的四道门。
- `score < 2` 时 `gap_type`、`severity`、`note` 三者必填。
  - `gap_type` ∈ 术语遮蔽 / 跳步 / 伪因果 / 边界失守 / 类比反噬 / 鹦鹉学舌 / 粒度错配 / 事实错误 / 未验证
  - `severity` ∈ 致命 / 重要 / 细节，**且与 score 强制绑定**：`score 1` 只能配「重要」，`score 0` 只能配「致命」。标轻会绕过 mastery 0.4 封顶，脚本会拦下。纯记忆型 `事实错误` 不污染机制链时可降级，需在 `note` 写明理由。
  - `note` ≥ 4 字符，**要摘用户原话的关键片段**，不要写「理解不足」这类空泛结论
- `resolves` — 本轮已闭合的历史 gap 的 `gid`（从 `gaps.md` 或 `state.json` 查）。不填则致命 gap 永远不闭合，mastery 会被永久封顶在 0.4。
- 该 session 的所有题都必须判分，漏判会被拒绝；重复 `record` 同一 session 会被拒绝。
- 校验是先全量后落盘：任一条不合法则整个文件不生效，改完重跑即可。

## notes.md — 费曼笔记（Phase 6 产出）

**前置条件**：无未闭合的致命 gap，且各概念 mastery ≥ 0.8（`status` 会给结论）。未达标就写笔记，等于把错误理解固化成文档。

```markdown
# 费曼笔记 · <title>

## 0. 一句话本质
禁用领域术语，≤ 40 字。写不出来就是 G1 没过。

## 1. 给外行的类比
类比 + **失效声明**：「这个类比在 X 处不成立」。
没有失效声明的类比是有害的（检测器 5）。

## 2. 机制链
A —(主语+动作)→ B —(主语+动作)→ C
每步标注 [已验证 #n] / [推断]，编号指向 sources.md。
不许出现「然后就…」「自然就…」。

## 3. 边界与代价
- 失效场景（具体输入，不要写「极端情况下」）
- 换来的代价 / 牺牲的性质
- 什么情况下不该选它

## 4. 我曾以为（Gap 复盘）
逐条：我原以为 X → 实际是 Y → 我为什么会这样想。
**这一节是整份笔记的核心价值，不要省略或压缩成一行。**

## 5. 常见误解
含 sources.md 登记的信源冲突、T4 流传的错误说法、以及我自己在 Phase 2 讲解里犯过又修掉的错。

## 6. 未解问题
标 `未知` 的那些，以及下一步该读什么（给出具体信源，不写「以后再说」）。

## 7. 信源
T1/T2 清单 + 抓取日期。
```

**第 4 节的写作纪律**：必须基于用户在 Phase 3–5 的**原话**（即 `gaps.md` 里 `record` 自动记下的 `detail`）整理，不要美化、不要替换成你的解释、不要写成中性描述。「我原以为 render 阶段 setState 没问题」是可复现的心智模型诊断，「对 render 阶段的纯度要求理解不足」则没有诊断价值。

## 可视化讲解图（Phase 2 或 Phase 6 产出）

用 Codex 的 `visualize` skill 生成（也可以直接写 HTML / Markdown 图）。产物放 `<dir>/<slug>/figures/`。

**何时该做**：机制类主题——有状态流转、时序、数据流、因果链。清单型 / 记忆型主题（API 列表、术语表、考点罗列）不要做图，没有额外价值。

三种图型：

| 图型 | 用于 | 要点 |
|---|---|---|
| 机制流程图 | 状态/数据流 | 节点标**主语+动作**，边标触发条件 |
| 时序图 | 有并发/异步/中断语义 | 必须画出中断与恢复，不能只画一条直线 |
| 边界对比图 | G3 训练 | 正常路径与失效路径并排，差异处高亮 |

几条硬要求：

- 图里每个断言都能追溯到 `sources.md` 编号（节点上标 `#n`）。
- **必须画出边界/失效那条路径**。只有 happy path 的图会强化「边界失守」这个 gap。
- 交互只做有用的：点击节点展开该步细节 + `source_ref`，便于回源。不加装饰性动画。
- 图不是讲解的替代品：**先讲后图**。

**图的第二个用途（更重要）**：它是 Phase 3 的 L2 换表征探针载体。让用户指着图把流程讲一遍——他在哪个节点卡住、哪条边讲不出触发条件，gap 就在那里。这比纯口头复述定位精度高得多，尤其对时序与并发类主题。
