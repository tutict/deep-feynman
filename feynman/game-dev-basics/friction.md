## 一、落在本轮两个新命令上（已修）

1. **`gaps` 的「回源坐标」列把表格撑爆。**
   `bank.json` 的 `source_ref` 实际常是一整句（如「年报 第53页；sources.md claim #4」），不是坐标。
   塞进表格后每行都换行，整张表没法看。
   → 改为每行下方单独一行 `↳ 回源: …`。用例 E7。

2. **`notes --scaffold` 第 7 节的分级靠猜。**
   台账里只有 claim 表带「级」列，「一手信源」表没有，于是 IGDA 框架（T2）、Rami 那篇（T3）被整表当成 T1。
   → 「一手信源」表支持「级」列（T1/T2/T3），第 7 节按它分级；没有该列时才整表当 T1。用例 E8。

## 二、指向新命令 / 新机制（记入 backlog，本轮不做）

3. **判分 taxonomy 与 score 绑定打架。**
   检测器自带默认严重度（「粒度错配 = 细节」「边界失守 = 重要」），但脚本硬绑「score 0 必须致命」。
   两者冲突时只能二选一，判分时得反复权衡。
   → backlog：给 severity 一张显式的「检测器 × score」映射表。

4. **bank 的 `reference_answer` 把某些门标成「加分」，脚本却按机械映射判。**
   例如 q12 的 G2 是「加分」，但 G2 为 false 会把分数直接压到 0（G1 或 G2 为 false → score 0）。
   「加分门」这个说法在脚本里没有对应。
   → backlog：让 bank 声明「必过门 / 加分门」，脚本按声明判分。

5. **学习者答「不清楚」时，九检测器里没有对应项。**
   既不是「跳步」也不是「未验证」；只能就近塞一个，分类会失真。
   → backlog：加一个「空白 / 未作答」检测器，或明确映射到某一条。
