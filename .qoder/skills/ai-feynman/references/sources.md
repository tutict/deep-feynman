# 取证协议

Phase 1 的操作手册。**用户会完整继承你讲解里的每一个 gap，而且因为是你说的，他不会怀疑。** 所以取证不是准备工作，它决定了这个 skill 是学习工具还是幻觉放大器。

## 首要原则：不得凭记忆讲解

任何具体断言——数字、默认值、名称、顺序、API 签名、版本行为、因果关系——都必须来自**本次实际读取**的材料。

- 记忆与抓取结果冲突时，**一律信抓取**，并把"我原本以为"记进 `sources.md` 的备注列。这往往是一个普遍误解，正好拿去出题（`type: counterexample`）。
- 不能实抓（付费墙、内网、用户未提供）→ 该断言标 `未知`，讲解中显式声明，**不要圆过去**。
- 每条 claim 登记进 `<dir>/<slug>/sources.md` 台账，缺登记的 claim 不允许出现在讲解里。

三级标注，讲解与笔记中必须可见：

| 标注 | 含义 | 使用条件 |
|---|---|---|
| `已验证` | 有 T1/T2 信源直接支撑，本次实读 | 可断言 |
| `推断` | 从已验证事实合理推导，但源材料未直接陈述 | 必须写出推理链 |
| `未知` | 查不到、或信源等级不足 | 必须显式声明不知道 |

## 信源分级

| 级 | 内容 | 用途 |
|---|---|---|
| **T1** | 源码本身、正式规范（RFC / W3C / ECMA / 语言标准）、作者本人论文、官方文档的 normative 部分、数据库 schema、测试用例 | 唯一可支撑具体断言 |
| **T2** | 官方工程博客、维护者写的设计文档 / ADR、同行评审论文、官方教程 | 可支撑机制与设计动机 |
| **T3** | 技术书籍、知名工程师的深度文章、会议演讲 | 只能找方向，不能下结论 |
| **T4** | 论坛问答、聚合博客、AI 生成内容、无署名文章、SEO 内容农场 | 只能当线索，必须回溯到 T1 |

硬性规则：

- 数字、默认值、名称、顺序、版本行为 → **必须 T1**。
- T3/T4 指向的方向，找到 T1 后才可写进讲解；找不到就标 `未知`。
- StackOverflow 类答案不得直接引用，必须把它指向的规范条目或源码位置读一遍。
- 冲突消解：T1 > T2 > T3 > T4。同级冲突取**更新的一手来源**，并把冲突本身登记为常见误解候选（出题素材）。
- 每条登记必须带**抓取日期**——网页会变，代码会改。

## 五类输入的取证流程

### A. 代码库 / 模块

用 `Grep` / `Glob` / `Read`，**读真实代码**。

- 追到实际执行路径，不要停在入口文件或 README。README 描述的是意图，代码是现实。
- `source_ref` 写成 `path/to/file.ts:123`，且必须是你**真读过**的行号——不许猜行号。
- **测试用例是行为的最佳一手信源**（T1）。想知道"边界在哪"，先读测试。
- `git log` / `git blame` 给出设计动机与当时的取舍，这是 G3（代价）和替代设计追问的弹药。
- **注释不可信**（会腐烂）。注释与代码冲突时以代码为准，且这个冲突本身就是值得讲的点。
- 别只读 happy path：找 error 分支、fallback、`TODO`/`FIXME`、被注释掉的代码。

### B. 论文 / 文档 / 规范

- 用 `Read` 读原文；PDF 超 10 页必须给 `pages` 参数分段读。
- `source_ref` 写 `论文 §3.2` / `spec 第 4.1 节` / `RFC 9110 §8.3`。
- 区分**规范条文**（normative，"MUST/SHOULD"）与**作者评论**（non-normative、示例、后记）。前者是 T1，后者最多 T2。
- 读论文的消融实验与 limitation 章节——那是 G3 边界与代价的直接来源。
- 规范有版本：引用必须带版本号或日期。

### C. 课程 / 考点

- 先取官方大纲，建**覆盖度矩阵**：大纲考点 × 是否已取证 × 是否已出题。未覆盖的考点不允许出 `score 0` 判定题。
- 教材版本很关键：不同版次章节号与结论都可能变。
- 考点与工程现实冲突时（教材过时），**两个都讲**，并明确标注"考试答 A，实践中是 B"——这本身是高价值 gap。

### D. 链接 / 笔记 / 碎片

- 用户给的 URL 一律先 `WebFetch` 实抓，不要凭 URL 猜内容。
- 碎片笔记必须追到一手信源：笔记里每个结论问一句"这出自哪？"，追不到就标 `未知`。
- 用户自己的旧笔记可能**本身就错**。发现与 T1 冲突时，这是最高价值的 gap——直接登记为 `事实错误` 素材。

### E. 网络自主检索（用户只给主题、没给材料）

这是最需要纪律的一条路径，因为检索结果里 T4 内容占多数。

1. **先列候选，再深入**。用 `WebSearch` 找到 5–8 个候选信源，按 T1–T4 分级，做成清单给用户过目：
   ```
   建议信源（主题: <X>）
   T1  <官方规范/源码仓库>          — 支撑: 具体断言
   T2  <官方工程博客 / 作者论文>     — 支撑: 设计动机
   T3  <某书 / 某深度文章>           — 仅作背景
   ```
   等用户确认或增删，再抓取。不要闷头读完一堆 T4 就开讲。
2. **主动找一手**：搜到 T3/T4 后，顺着它的引用往上找 T1（官方文档、源码仓库、原论文）。
3. **搜版本号**：主题涉及框架/库时，检索词带版本；结论注明适用版本区间。
4. **交叉验证**：任何反直觉或关键的结论，至少两个独立信源，且其中一个必须是 T1。
5. **时效**：`WebSearch` 结果注意发布日期，过时结论要标注。当前日期以环境提供为准。
6. 引用外部检索内容时，回复末尾按系统要求附来源链接。

## 取证预算与停止条件

- 每个概念**至少 1 个 T1 信源**才可进入 Phase 2 讲解。
- 单概念取证超过约 5 次工具调用仍拿不到 T1 → 标 `信源不足`，讲解中显式声明，并且**该概念不出 `score 0` 判定题**（无法可靠判分）。同时告诉用户"这一块我给不了一手依据"。
- 宁可少讲、讲准，不要为了覆盖面把 `推断` 混进 `已验证`。

## sources.md 台账格式

```markdown
| # | claim | 信源 | 级 | 抓取日期 | 状态 |
|---|-------|------|----|----------|------|
| 1 | render 阶段必须纯，中断重跑会执行两次副作用 | ReactFiberWorkLoop.ts:1180 | T1 | 2026-10-18 | 已验证 |
| 2 | lane 用 bitmask 是为了 O(1) 合并优先级集合 | ReactFiberLane.ts:88 | T1 | 2026-10-18 | 已验证 |
| 3 | 该设计源于 2017 年的一次重构提案 | 官方 blog/2017/12 | T2 | 2026-10-18 | 已验证 |
| 4 | bitmask 宽度选 31 位与 JS 位运算的有符号性有关 | 无一手来源 | —  | 2026-10-18 | 未知 |
| 5 | 我原以为 lane 只有 5 个等级（实际 31 位） | 记忆，已被 #2 推翻 | — | 2026-10-18 | 已纠正 |
```

`claim` 列写结论本身，不写主题名；`信源` 列必须能直接跳过去核对。
