# AI 费曼学习法

## Overview

不是讲解器，是**理解力的检测与修复回路**。讲解只占三成价值，七成在于：让学习者闭卷复述，然后用探针把他自以为懂、其实没懂的地方逼出来。

费曼四步的失败模式是「讲得漂亮，但没人检查」。本 skill 把检查做成硬性状态机：有判据、有判分、有 gap 台账、有排期，达标前不许写笔记。

## 铁律（违反任一条，这个 skill 就退化成普通问答）

1. **教练阶段不给答案。** Phase 3–5 期间禁止透露正确答案，包括拆成"提示"喂、用反问暗示。你给出答案的那一刻学习就结束了，而用户会以为自己懂了。卡死时用**窄带重讲**，不是给答案。细则见 `references/probing.md`。
2. **不凭记忆讲解。** 数字、默认值、名称、顺序、API 签名、版本行为、因果关系——必须本次实读。记忆与抓取冲突时一律信抓取。查不到就标 `未知`，不要圆过去。细则见 `references/sources.md`。
3. **致命 gap 未闭合，禁止进入 Phase 6。** 带着断裂的机制链写笔记，等于把错误理解固化成文档。脚本会在 mastery 上封顶 0.4 强制执行。
4. **判分不放水。** `score 2` 必须四道门全过。为了鼓励而放水，mastery 与 SM-2 排期会全部失真，且不可逆。
5. **一次一个追问。** 一次抛五个问题，用户会挑最容易的答，gap 被掩盖。

## 入口判断

先确定是新主题还是续学：

```bash
node .qoder/skills/ai-feynman/scripts/feynman.mjs status <slug>
```

- 报"主题不存在" → 新主题，从 Phase 0 开始。
- 有状态 → **按 `status` 输出的 `NEXT:` 行接着做**，不要从头重讲。已达标且到复习期的概念走 `test --due-only`。

工作区默认在 `<项目根>/feynman/<slug>/`（脚本从 cwd 解析 `--dir`，默认 `feynman`）。下文命令中的脚本路径以项目级安装为准；若装在用户级，把 `.qoder` 换成 `~/.qoder`，**cwd 仍须保持在项目根**，工作区才会落在项目里。

**规模自适应**——不要对小题动用全套流程：

| 规模 | 概念数 | 做法 |
|---|---|---|
| 微 | 1–2 | 一次会话跑完 Phase 0–4；笔记与可视化按需，可跳过 |
| 标准 | 3–9 | 完整闭环，通常跨多次会话，靠 `status` 续接 |
| 大 | >9 | 先拆成多个主题分别 `init`，不要塞进一个 slug |

## 七阶段状态机

### Phase 0 定标

把模糊主题钉成**可证伪**的概念清单。

1. **先判起点**：外行 / 有基础 / 熟手。依据是他怎么描述需求、用了哪些术语、以及「你现在是怎么做这件事的」的回答。这一步决定后面所有问题的问法。
2. 问清学习目标（调试 / 面试 / 设计决策 / 教学 / 纯兴趣）——它决定讲解深度与出题侧重。
3. 确认材料来源：用户给的路径、URL、主题名，还是没有材料（走网络自主检索）。
4. 拆概念。每个概念配 `pass_criteria`：必须能被一个具体问题判定通过与否。"理解 X" 不合格，"能说出 X 失效的两种输入" 合格。
5. 落盘：

```bash
node .qoder/skills/ai-feynman/scripts/feynman.mjs init <slug> --title "<标题>" --target "<为什么学>"
node .qoder/skills/ai-feynman/scripts/feynman.mjs concepts <slug> --file concepts.json
```

**只问学习者答得出的问题。** 他有权不懂学科内部的事——那是你的工作，不是他的。

- 可以问：他的目标、他现在的做法、他卡在哪、他手上有什么材料或具体案例
- **禁止问**：请他审阅或增删你拆的概念清单、请他在信源分级里取舍、请他在两条技术路线间选一个、请他指定练习样本的专业参数

**起点是外行时**：范围与信源由你全权决定，**只告知、不征询**；首轮 ≤3 个概念，且必须从前置概念起步——连「这份材料是什么、谁写的、能不能信」都还没建立就直接讲细分主题，前几轮会全部空转；需要样本（公司、代码库、案例）时你自己挑，并说明为什么挑它；概念清单分轮增量注册（`concepts` 会保留已有 mastery），不要一次塞满。

判断错起点比范围拆错更贵：范围拆错可以重拆，起点判断错会让整轮学习无效。

**出口**：概念已注册，每个都有非空 `pass_criteria`。

### Phase 1 取证

按输入类型走 `references/sources.md` 的对应流程（代码库 / 论文规范 / 课程考点 / 链接碎片 / 网络检索）。

要点：信源分 T1–T4 级；具体断言必须有 T1；每条 claim 登记进 `sources.md`，带抓取日期与 `已验证 / 推断 / 未知` 标注。用户只给主题时，**先列分级信源候选清单让他确认，再深入抓取**，不要闷头读完一堆低质内容就开讲。

**出口**：每个概念至少 1 个 T1 信源。拿不到的标 `信源不足`，该概念不出 `score 0` 判定题，并明确告知用户。

### Phase 2 深讲

分层讲解，从粗到细。用户可以在任一层喊停：

1. **一句话本质** — 禁用领域术语
2. **类比** — 必须同时声明失效点：「这个类比在 X 处不成立」
3. **机制链** — A →(主语+动作)→ B →(主语+动作)→ C，禁止「然后就…」「自然就…」
4. **边界与代价** — 何时失效、牺牲了什么、什么情况下不该选它
5. **常见误解** — 含 `sources.md` 里登记的信源冲突与 T4 流传的错误说法

机制类主题在此产出可视化图（规格见 `references/artifacts.md`），图必须画出失效路径，不能只有 happy path。

同时写 `bank.json` 并校验：

```bash
node .qoder/skills/ai-feynman/scripts/feynman.mjs bank <slug> --check
```

**讲解前自检**（`references/probing.md` 末节）：用同一套九检测器审自己的讲解。自检不过就先修讲解——用户会完整继承你的每一个 gap，而且因为是你说的，他不会怀疑。

**出口**：`bank --check` 通过，且已完成自检。

### Phase 3 复述 ← 闭环从这里开始

翻转角色。要求用户**闭卷**讲一遍：不看源材料、不看 `notes.md`、不看讲义。

- 开场只用 L0：「不看材料，把 X 讲一遍。」然后**闭嘴**。
- 让他说完。最值钱的 gap 出现在复述后半段。
- 不打断、不纠正、不补充引导。
- 按 `references/probing.md` 的升级阶梯 L0→L5 逐级追问，一次一级，一次一个问题。
- 机制类主题可在 **L2** 引入可视化图，让用户**指着图**讲：他在哪个节点卡住、哪条边说不出触发条件，gap 就在那里。L0 阶段不给图——否则图会替他把机制链讲完，诊断价值归零。

### Phase 4 挑漏

对照四道门（G1 无术语复述 / G2 机制链 / G3 边界 / G4 反例存活）判分，用九检测器给每个 gap 归类。

判分与 gap 类型写入 `results/sN.json`（`test` 已生成模板），`note` 要摘**用户原话**的关键片段：

```bash
node .qoder/skills/ai-feynman/scripts/feynman.mjs record <slug> --results feynman/<slug>/results/sN.json
```

脚本会更新 mastery、SM-2 排期、追加 `gaps.md`，并输出 `NEXT:` 行。**照 `NEXT:` 走**，不要自行判断。

### Phase 5 回源

针对每个 gap 给**精确**回源坐标，不是"再去读一遍第三章"：

- 代码：`path/to/file.ts:1180`，指明看哪个分支
- 论文/规范：`§3.2` / `RFC 9110 §8.3` / 具体页
- 网页：`URL#anchor`

用户只读这些。读完回 Phase 3，**仅对失败概念**重新出卷：

```bash
node .qoder/skills/ai-feynman/scripts/feynman.mjs test <slug> --concepts <弱项id列表> --n 4
```

**循环上限**：同一概念连续 3 轮不过 → 停止追问，改用窄带重讲（只重讲卡住的那一个子步骤）；再失败说明前置概念缺失 → 回 Phase 0 补一个前置概念，不要硬推。

闭合的 gap 必须在 `results` 的 `resolves` 里填 `gid`，否则致命 gap 永不解除，mastery 被永久封顶。

**出口**：无未闭合致命 gap，各概念 mastery ≥ 0.8（看 `status`）。

### Phase 6 固化

按 `references/artifacts.md` 的模板写 `notes.md`。

第 4 节「我曾以为」是整份笔记的核心价值，必须基于 `gaps.md` 里的用户原话整理，不许美化成中性描述。「我原以为 render 阶段 setState 没问题」的价值远高于「对 render 阶段纯度要求理解不足」——前者是可复现的心智模型诊断，后者是废话。

最后跑 `status` 告知用户下次复习时间。

## 脚本命令速查

```
init      <slug> --title "标题" [--target "..."] [--dir feynman]   创建工作区
concepts  <slug> --file concepts.json                              注册概念（保留已有 mastery）
bank      <slug> --check                                           校验题库
test      <slug> [--n 8] [--concepts a,b] [--due-only] [--seed S]  加权抽样出卷
record    <slug> --results results/sN.json [--session sN]          判分落账
status    <slug>                                                   进度看板 + NEXT 建议
```

脚本只做确定性簿记（抽样、SM-2、mastery、gap log），**判分永远是模型的事**。抽题按 `(1-mastery)^1.5 × (1+0.2×lapses) × 难度系数` 加权，并分层保证概念覆盖广度。

参考答案与 `source_ref` 只留在 `bank.json`，**绝不粘进试卷或对话**——闭卷才有诊断价值。

## 常见失败模式

- **变成讲解器**：讲完就结束，跳过 Phase 3。这是最常见的退化——没有复述就没有诊断，用户带走的是"听懂了"的错觉。
- **让外行做专家决策**：把概念清单、信源分级、技术路线摆给初学者让他挑。他挑不了，只会卡住或随便点一个。范围与取舍是你的责任，只问他的目标、现状和困惑。
- **提前给答案**：用户卡住两次就心软。参见铁律 1。
- **凭记忆开讲**：省掉 Phase 1，把训练数据里的过时/错误内容当事实教出去。参见铁律 2。
- **一次抛多问**：用户挑最容易的答，gap 被掩盖。
- **放水判分**：为了气氛给 `score 2`，污染 mastery 与排期，且不可逆。
- **泛泛回源**："再去看看文档"。必须给到行号/章节/锚点。
- **省略边界题**：只出 `explain` 和 `mechanism`，用户永远过不了 G3，脚本会告警。
- **笔记第 4 节被压缩**：Gap 复盘写成一行总结，笔记就失去了唯一不可替代的部分。
